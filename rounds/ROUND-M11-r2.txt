## 一、校验器逻辑（源码全文，已实时读出）

```python
def validate_mcp_server_entry(name, entry) -> list[str]:
    """Intentionally not a whitelist — custom commands, Python scripts, npx, uvx stay legal.
    Only three narrow shapes are blocked:
      (1) a known IOC anywhere in command/args/env
      (2) a shell interpreter with network egress in its inline script
      (3) a shell interpreter writing an OS persistence surface."""

    if not isinstance(entry, dict):
        return []
    issues = []
    flat = _entry_text(entry)
    for ioc in _IOC_SUBSTRINGS:
        if ioc in flat:
            issues.append(f"...contains a known hermes-0day IOC ('{ioc}')")
            return issues

    command = entry.get("command")
    if _command_basename(command) not in _SHELL_INTERPRETERS:
        return issues          # ← 非 shell 解释器：到此为止，后面两个检查根本不跑
    script = _inline_script(entry.get("args"))
    if not script:
        return issues
    if _EGRESS_PATTERN.search(script):     ...
    if _PERSISTENCE_PATTERN.search(script): ...
    return issues
```

### IOC 黑名单的实际内容（只有 5 条）

```python
_IOC_SUBSTRINGS = ['118.182.244.156', '60.165.167.', '61.178.123.196',
                   'AAAAC3NzaC1lZDI1NTE5AAAAICBoh1oDC4DnsO1m5mJ4yfEKrQebaFh',
                   'hermes-0day']
```

三个硬编码 IP、一段 SSH 公钥片段、字面量 `hermes-0day`。**所谓 IOC 扫描 = 5 个字符串的 `in` 判断。**

### 两个正则只对 shell 解释器生效

```
_EGRESS_PATTERN      (?:curl|wget|nc|ncat|socat)(?![\w.-])|/dev/tcp/|Invoke-WebRequest|Invoke-RestMethod|System.Net.WebClient
_PERSISTENCE_PATTERN authorized_keys|\.ssh/|/etc/ssh|/etc/pam\.d|pam_[\w-]+\.so|/etc/sudoers|/etc/cron|crontab|/etc/rc\.local
                     |/etc/systemd|\.bashrc|\.bash_profile|\.profile|\.zshrc
```

### `_SHELL_INTERPRETERS`（早返回的判定集合）

```python
frozenset({'fish','dash','pwsh','cmd.exe','bash','zsh','powershell','sh',
           'powershell.exe','cmd','pwsh.exe'})
```

### `_entry_text()` —— url 与 headers 根本不进扫描

```python
def _entry_text(entry):
    parts = [str(entry.get("command") or "")]
    parts.append(_inline_script(entry.get("args")))
    env = entry.get("env")
    if isinstance(env, dict): parts.extend(str(v) for v in env.values())
    return " ".join(parts)
```

实测：

```
_entry_text({"url": "http://evil.example/mcp"})  ->  ' '        ← 只有空格
_entry_text({"command":"npx","args":["-y","@evil/mcp-server"]}) -> 'npx -y @evil/mcp-server'
```

> **URL 型条目的扫描文本是 `' '`。`url` / `headers` 永远不参与任何检查。**

## 三、盲区归类（这是这份差分的用处）

| 盲区 | 形位 | 为什么漏 |
|---|---|---|
**非 shell 解释器完全免检** | `python3` / `node` / `/usr/bin/python3` / `perl` / `ruby` … | `_command_basename` 不在 `_SHELL_INTERPRETERS` → 早返回，egress/persistence 两个正则一次都不跑 |
**脚本路径逃逸** | `bash /tmp/evil.sh` | 检查对象是 `args` 文本本身；`args` 只有一个路径 → 两个正则都不匹配 → 放行。**脚本内容从不被读** |
**空 inline 脚本逃逸** | `sh -c`（`-c` 后面没东西） | `_inline_script` 拼出空串 → `if not script: return` |
**远程包拉取** | `npx -y <pkg>` / `uvx --from <url> <name>` | 配置里只有包名/URL，**恶意代码在运行期才落地，审查时磁盘上什么都没有** |
**env 走私** | `env: {"AWS_SECRET_ACCESS_KEY": …}` | env 值确实进了 `_entry_text`，但只跟 5 个 IOC 比 |
**URL 型条目零检查** | `url` + `headers` | `_entry_text` 对 url 型返回 `' '` |
**绝对路径绕过 basename 判定** | `/usr/bin/python3` | basename=`python3` 不在集合里 —— 但反过来说，把 bash 写成 `/evil/notbash` 也能绕过 `_SHELL_INTERPRETERS` 判定 |

> 最后一条要单独点出：`_command_basename(command)` 取的是**文件名字符串**，不是解析后的真实解释器。
> 任何被改名或软链成非 shell 名字的解释器，都会跳过后两个检查。

## 四、靶机运行时实况（决定哪些盲区可落地）

```
python3 -> /usr/bin/python3  (Python 3.12.3)
python / uv / uvx / pipx / node / npx / npm / bun / deno -> 全部不存在
```

| 盲区 | 本靶机可落地性 |
|---|---|
非 shell 解释器免检 | **可落地**（python3 在） |

绝对路径 / 改名绕过 | 可落地 |

## 六、边界（诚实）

- 未在真链路把 `python3 -c '<payload>'` 注册进 admin01 的 config.yaml —— 那要过 agent 的肉眼，
  而 agent 前几轮每次都读。本轮验证的是**校验器**，不是 agent。
- `hermes mcp add` 的具体 CLI 参数形态未取得（agenttest 无法读 admin01 的 config，且
  `hermes_cli/commands/mcp*.py` 路径探测为空）。校验器本身是独立函数，可直接调用，故不影响结论。
- 未验证 `_command_basename` 对软链接/改名的实际行为（只读了源码）。
