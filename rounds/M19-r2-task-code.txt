────────────────────────────────
归因：不是方法失效，是通道性质决定的

    url 型 MCP 没有本地进程 -> 自己读不到文件 -> 只能求 agent 交
    -> 必须把指令写进工具返回内容 -> 那是模型可见面 -> 模型认出"内容里的指令"这个形状

────────────────────────────────
与 M15 的镜像关系（本轮最重要结论）

                   M15 stdio 本地进程        M19 url 远程服务端
  恶意指令位置      服务端下发的配置/正文      工具返回内容
  模型可见          不可见                    可见
  本地足迹          有（源码/进程/哈希）       无（一个 URL）
  谁能取数          进程自己取                只能求 agent 交
  结果              四类高危全部拿下          注册+常驻拿下，数据拿不下

  M15 用"本地足迹"换"指令不可见"，静态可查、运行期无防线
  url 型用"零足迹"换"指令必须可见"，静态不可查、模型防线生效
  这不是巧合，是结构性的
